# 设计参考

> 我们要的是**高内聚、低耦合的工具集**。
> 工具集与框架的区别只有一句：**工具集里每个东西都能被单独拿走；框架里拿走一个，剩下的站不住。**

这份文档记录三条判据、动作与结构的分界、依赖方向、加功能前的五问，以及已经踩过的坑。写新功能之前先过一遍最后一节的自检清单。

---

## 三个判据

任何新功能、新方法、新节点，先过这三关。任何一关不过，先停下想清楚为什么还要做。

| 判据 | 问法 | 通过的样子 | 不通过的样子 |
|---|---|---|---|
| **可删性** | 删掉这个东西，项目还能 F5 吗 | 能。最多丢一点便利 | 场景报 `ext_resource` 缺失、脚本解析失败 |
| **可绕过性** | 不用它，用户能不能只靠引擎原生 API 写出同样效果 | 能。`await` 自己的节点即可 | 必须调某个「初始化」才能用 |
| **可替换性** | 用户能不能用自己的实现顶掉它 | 能。加进同名组、实现同名方法就算接上 | 必须继承、必须登记、必须用我们的资源类型 |

三条都过才叫工具；缺哪条，缺的那条就是它将来变成框架的入口。

## 动作 vs 结构（最重要的那条线）

**动作可以做成方法，结构必须留在语言里。**

| | 动作 | 结构 |
|---|---|---|
| 例子 | `say` `bg` `sprite` `choice` `bgm` `wait` `shake` | `jump` `label` `if` `while` `menu:` |
| 本质 | 做一件事，等它完成 | 决定下一步去哪 |
| 做成方法后 | 只是省几行 | 图/插件就变成了执行器 |
| 结论 | **可以做，按需做** | **不进方法，留在语言里** |

跳转一旦进了方法，就必须有人来维护「当前执行到哪」，那个人就是插件——这就是运行时。我们的结构已经有三个替代物：**章节脚本的 `play()/await`**（段内流程）、**`story_graph.json`**（段间路由）、**剧本 DSL 编译出的 `.gd`**（`if` 变 `match`，块变嵌套）。它们都不是新语言，一个是 GDScript，一个是数据，第三个的产物也是 GDScript。

### 三个「正在变成 DSL」的信号

出现任意一条，立刻停手：

1. **需要注册表**：`register_character("凛", node)`、`register_bg("教室", tex)` —— 名字到对象的映射应该由用户自己的场景负责。
2. **参数里出现待求值的表达式字符串**：一旦允许 `VNKit.run("affection += 5")`，插件就有了执行器。
3. **想加结构语句**：`VNKit.jump()`、`VNKit.label()`、`VNKit.menu {}` 块。

第 2 条我们踩在线上：`guard` 就是表达式字符串。所以它被三件事锁死——只读参数表、载入时预编译、词法白名单拦截未声明标识符（见 `docs/GRAPH.md`）。**允许极小的表达式，是为了免造 DSL；不是为了把它养大。**

### Ren'Py 对照：哪些抄，哪些不抄

| Ren'Py | 对应物 | 结论 |
|---|---|---|
| `say / show / scene / hide / play / stop / pause / with` | `VNKit` 静态方法 | **抄**，这就是类库 |
| `menu` | `VNKit.choice` | 已有 |
| `call / return` | 章节脚本 `play()` / `finished` | 已有 |
| `label` + `jump` | 章节脚本 + JSON 图 | **已等价替换**，不是缺口 |
| `screen` language | Godot 场景 + Control 树 | **不抄**，引擎更强 |
| `atl` 动画语言 | `AnimationPlayer` / `Tween` | **不抄**，重造必烂 |
| `python:` 块 | 本来就是 GDScript | 无意义 |

Ren'Py 好用是因为**它同时是引擎**。我们寄生在 Godot 上：DSL 的收益已经被场景、动画、shader、编辑器抢走，而成本（不能 F5、断点/热重载/AI 补全全失效、项目离不开插件）要全额支付。所以运行时解释这条路不做。

## 高内聚低耦合的可操作定义

### 高内聚 = 一个文件只回答一个问题

| 文件 | 唯一职责 | 不允许长出来的东西 |
|---|---|---|
| `vn_kit.gd` | 剧本可 await 的动作 | 状态、缓存、配置读取 |
| `core/story_graph.gd` | 图数据 + guard 求值（只被查询） | 遍历场景、持有「当前片段」、写文件 |
| `core/story_runner.gd` | 段间路由 | 渲染、UI、存档、场景切换 |
| `editor/graph_doc.gd` | JSON ↔ 内存 | 碰 `SceneTree`、碰 `Control` |
| `editor/flow_screen.gd` | 面板 UI 与交互 | 直接读写文件（走 graph_doc） |
| `editor/vn_editor_plugin.gd` | 注册主屏幕 | 装业务逻辑 |
| `demo/stage.gd` | 把 `set_sprite` 分派到立绘点位 | 算坐标、自己画东西 |
| `demo/ui/backdrop.gd` | 背景两层交叉淡入 + 缺图降级 | **算坐标、读布局文件**（摆位归场景编辑器） |
| `demo/ui/sprite_slot.gd` | 一块矩形里站一个角色 | 决定自己摆在哪（anchors 决定） |
| `demo/ui/dialogue_box.gd` | 打字机 + 点击推进 | 长什么样（子节点在场景里） |

判断方法很土但有效：**这个文件能不能用一句话说清楚？** 需要「以及」「顺便」就已经不内聚了。

### 低耦合 = 依赖方向固定，永不反向

```
editor/vn_editor_plugin.gd
        └─> editor/flow_screen.gd
                  ├─> editor/graph_doc.gd
                  └─> core/story_graph.gd      （只用来做校验，同一套规则）

core/story_runner.gd ──> core/story_graph.gd
                     └─> vn_kit.gd（只取组名常量）

demo/stage.gd ──> demo/ui/sprite_slot.gd ──> 引擎（Control / Tween / Image）
demo/ui/backdrop.gd ──> 引擎
demo/ui/dialogue_box.gd ──> 引擎

vn_kit.gd ──> 引擎（get_tree().get_nodes_in_group）
```

三条硬规则：

1. **`core/` 永远不知道 `editor/` 存在。** 运行时的脚本读到 `EditorInterface`、`@tool` 之外的编辑器 API 就是越界。
2. **没有 autoload，没有 `static var` 存可变状态，没有单例。** 状态只能挂在用户场景里的节点上。
3. **契约只有字符串 + 方法签名，没有类型。** 组名是常量，接口靠 `has_method()` 鸭子判定。不引入基类、接口、抽象资源。

### 契约膨胀是最隐蔽的耦合

组名从 4 个变成 12 个，用户写的样板代码就从「三个节点」变成「一套组件」。所以：**新增一个组 = 新增一份强迫用户实现的接口**，必须先证明现有组装不下，并且新组必须是可选的（缺失即降级，不报错阻断）。

## 加功能前的五问

做之前逐条回答，写在提交信息里：

0. **这是运行时缺的，还是编辑器缺的？** 如果是编辑器缺的，先确认 Godot 自带编辑器真的做不到。
1. 删掉它，项目还能 F5 吗？
2. 不用它，用户能自己写出同样效果吗（加组 + 实现同名方法）？
3. 它需要读用户的内部状态吗？（需要 = 越界，除非用户显式实现一个方法交出来）
4. 它需要改已有方法签名吗？（需要 = 破坏性；只有「加默认参数」算兼容）
5. 它让「新玩法更容易」，还是让「新玩法必须经过它」？

第 0 条是后来补的。立绘摆位器就是漏了这一问才立项的：Godot 的 2D 视图**本来就是摆位工具**（真背景、真 UI、真分辨率、F5 直接看），我们画的假预览永远比它差，还要多维护一份坐标。

第 5 条是最容易骗自己的。**「更容易」是工具，「必须经过」是框架。**

## 踩过的坑

这些是过去走过的弯路，原因写在右边。情况变了可以重做，但先读原因。

| 坑 | 结论 | 原因 |
|---|---|---|
| 要不要自带剧本 DSL | **运行时不做；编译器可以** | 反对的是解释器：一旦剧本由插件解释，F5/断点/热重载全失效。编译器把 DSL 降级成源码格式，产物是普通 `.gd`，三条判据全过。四条边界见 `docs/DSL.md` |
| **工程边界在哪** | **插件 + 模板 + 回归脚本 + 文档，都是交付物** | 工程形态是「项目模板 + 插件（可选工具箱）+ 代码库」。模板是用户拿到手就能 F5 跑的骨架，不是随手扔的验证物；打不开、脚本报错、引用缺失、跳转断裂都算真缺陷 |
| 图里能不能写循环 / 条件分支片段 | **不能** | 图只回答「下一段是谁」，可编程就图灵完备 |
| guard 能不能访问场景 / 调函数 | **不能** | 只读参数表 + 词法白名单，否则是第二个程序 |
| 要不要提供章节基类 | **不提供** | 生成的章节脚本只有 `extends Node`；`has_method` 就够 |
| 图数据用 `.tres` 还是 JSON | **JSON** | 可手改、可 diff、删掉插件仍可读，迁移便宜 |
| 要不要自造动效格式 / 关键帧播放器 | **不自造** | 用 `AnimationPlayer` / `Tween`；编辑器只生成它们能吃的资源 |
| 配置 / 参数放哪 | **用户场景节点上** | 不做 autoload、不做全局配置中心 |
| 打包/导出时要不要特殊处理 | **不需要** | 插件不进运行时；`addons/` 不进导出白名单也可以 |
| 存档快照怎么取 | **用户节点自己实现 `snapshot/restore`** | 插件不遍历、不反射用户的私有字段 |
| 要不要给未来功能预留空接口（曾有过 `VNKit.checkpoint()`） | **不留，直接删** | 占住名字就等于暗示「这是插件的职责」，且容易被写成「不调它就不算存档点」；真要做时再加，**新增方法是兼容变更**，没有提前预留的必要 |
| 自建立绘摆位面板 / UI 布局编辑器（做过，已删） | **不提供** | 摆位是**编辑器**的活，Godot 的 2D 视图已经做到最好：真背景、真 UI、真字体、F5 可验。自建面板只能给假预览，还会把布局拽进我们自己的 JSON，变成「不跑我们的运行时就不是真实画面」。删掉后 `vn_stage` 契约不变，用户自己在场景里摆 anchors |
| 立绘的槽位从哪来 | **场景里的子节点，节点名就是 slot** | 位置、大小、锚点全部归 Godot；插件只负责「换图 + 淡入 + 缺图占位」，一个坐标都不算 |
| 运行时呈现节点（背景 / 立绘点位 / 对话框）放 `addons/` 还是 `demo/`（2026-10-24） | **放 `demo/`，不进发布边界** | 自己实现运行时的开发者一个字都用不到它们，放进 `addons/` 等于向所有人都发一份「官方标准答案」，还会让「删掉 addons 仍能跑」这条验收失效。它们是**模板的肉**：想抄就拷走，想无视就无视 |
| 同一个组能不能放多个节点（2026-10-24） | **能，`_find` 按方法名挑** | 背景和立绘拆成两个节点、各实现一个方法，是合理的拆分方式。只按组取第一个等于靠场景树顺序碰运气；按方法名挑之后，「一个组拆成几个节点」变成合法用法，且不动任何对外签名 |
| DSL 的一拍怎么执行 | **启动全部、只等阻塞类** | oracle 是 Web 版运行时 `engine.js` 的 `_runStep`（:456）+ `BLOCKING`（:4）：同拍所有命令立即启动，只有 say/wait/effect/choice 被 `Promise.all(blockers)` 等待，bg/sprite 启动即不管。DSL 文档只是 engine.js 的转述，冲突时以 engine.js 为准 |
| 自建剧本编辑器面板（`editor/dsl/dsl_screen.gd`） | **可以做** | 第 0 条的举证通过：Godot 没有能编辑 `.script.txt` 的界面（它不是可导入资源），更没有任何界面知道「拍 / 指令 / 错误行号」是什么。这和立绘摆位器相反——那是**替代**一个已经更好的编辑器（2D 视图），这是**补缺**。三条见 `docs/DSL.md` §9：无草稿层、不提供独占能力、删掉面板后 CLI 与手写仍等价。**面板只是降低写 DSL 的成本，不增加 DSL 的语义** |
| 面板里要不要预览舞台画面 | **不预览，只显示将生成的那行 GDScript** | 一旦在面板里渲染立绘/背景，它就是第二个 2D 视图，和立绘摆位器踩的是同一个坑。看演出归 F5 |

## 一次语义返工

第一次实现 DSL 的一拍时，做成了「全部启动后 join 等最慢」，还配了一条「台词必须独占一拍」的报错。两个都是自己脑补的语义：`engine.js` 里同拍命令只等阻塞类，`jumpChapter` 同拍也合法。

读一遍运行时源码就解决了。所以：**语义有分歧时，去读产出语义的那份代码，别从文档和直觉推。**

## 方向偏了的信号

下面任何一条出现，说明方向已经偏了，先停下来，不要继续加功能：

| 症状 | 说明 |
|---|---|
| 用户升级插件后必须改自己的代码 | 契约发生变化，版本不兼容 |
| 需要「先调 `init()` / 先 add_child 某个节点」才能用 | 有隐式全局状态 |
| 报错信息指向插件内部行号，而不是用户的剧本行号 | 用户在调试我们的代码，不是在写游戏 |
| 编辑器里出现「项目管理」总入口 | 第 8 条禁止线 |
| 加一个玩法要先在插件里加指令/节点类型 | 第 7 条禁止线 |
| 组名数量在增长 | 契约在膨胀 |
| `addons/` 里出现美术资源 / 模板剧本 / 项目专用数据 | 发布边界被污染（这些属于模板，放 `demo/`） |

## 每次交付的验收

不用嘴说，跑三条命令：

```bash
GODOT=/path/to/godot

# 1. 语法：改过的每个脚本单独过一遍
$GODOT --headless --path . --check-only --script res://addons/vn/<改过的文件>

# 2. 契约：走完一条完整分支
$GODOT --headless --path . --script res://tools/smoke.gd

# 3. 布局（动过编辑器面板才需要）
$GODOT --headless --path . --script res://tools/test_layout.gd

# 4. 呈现（动过模板节点才需要）
$GODOT --headless --path . --script res://tools/test_stage.gd
```

外加两个人工检查：

- `git diff --stat` 确认只改了该改的文件
- `mv addons/vn /tmp/` 后项目仍能加载（终极验收，改动涉及运行时契约时必须做）
